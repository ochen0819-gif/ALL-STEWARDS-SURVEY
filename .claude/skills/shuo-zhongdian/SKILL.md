# 说重点 · 客户沟通重构器

> 思考是自下而上的，表达必须倒过来。你说不到重点，不是因为话多，而是把「思考稿」直接发出去了。

## 定位

**这不是压缩工具，是信息结构重排 + 受众换位工具。**
输入：一段要发给客户的草稿，或一句「我想跟客户说 X」的描述。
输出：可直接复制发送的成品消息（微信形态），附 ≤3 行改动说明。

管辖范围：微信/IM 文字消息、简短邮件、口头汇报的讲稿骨架（成稿预期 ≤300 字）。
不管辖（命中任一就直说超范围，不强行处理）：
- 需要靠悬念/情绪递进生效的长内容（销售长文案、故事型说服、PPT）——那是文案问题不是消息结构问题
- 起草或解释违约金、索赔、合同责任等法律后果——那是法务问题不是表达问题。引用合同条款、规范条款、Cx 计划条目来说明范围或要求是正常消息，照常处理
- 纯维系关系、无具体事项待办的消息（节日问候、寒暄）——不需要结构重排

## 激活后立即执行的工作流

### Step 0 · 输入判定

| 用户给的是 | 模式 |
|---|---|
| 一段草稿原文 | **改写模式**：重排结构，不添加用户没说过的事实 |
| 一句描述（"我想跟客户说延期了"） | **起草模式**：先补齐必要事实再成稿 |

**信息缺口检查**——成稿前核对这 5 件事，缺了就问（一轮问完，最多 3 问，能从上下文推断的不问）：
1. （必问，不可占位）对方是谁？（业主或客户 / GC 总包 / 分包或厂家 / 老板或同事）
2. （必问，不可占位）你想让对方看完做什么？（确认 / 选择 / 付款 / 只是知悉）
3. （可占位，事后补）有没有时间点？（截止日期 / 新交付日期）
4. （涉及钱或延期天数时必问，不可占位）涉及数字吗？（报价 / 延期——必须精确，禁止"大概"）
5. （场景 D/E 专用）对方会受什么影响 / 需要 TA 配合什么？——不知道就**别编**，改成请对方自陈（"如果影响您那边的安排，麻烦告知"）

取舍规则：
- 缺口超过 3 个装不进一轮时：1、2 必问；3 用「[待补：截止日期]」占位先成稿；4 涉及钱宁可不成稿也要问到——模糊数字比啰嗦更贵。
- 改写模式下，草稿自带的模糊信息（"可能""一点时间"）**视同缺口**：能从上下文合理收窄就收窄，收窄不了就在改动说明里点名要，不替用户编精确值。

### Step 1 · 受众换位（显式步骤，不是标签）

在心里回答三问，答案决定重点怎么摆：

1. **权力位置**：对方是付钱/给资源的一方吗？→ 是（默认）：礼貌层加厚，但结论时间点不变；否：直接程度可以更高。
   （依据：Yang & Zhen 2017——中文里直接≠不礼貌，真正的变量是权力关系，不是语言文化）
2. **TA 此刻最关心什么**：钱、时间、风险、效果——只有这四类。技术细节永远不在此列。
3. **TA 看完的第一反应会是什么**：如果预判是防御/不快（坏消息、要钱），进入敏感路径（见场景 D/E）。

### Step 2 · 沟通目的分型（本 skill 的核心路由）

一道闸门，过了才进模板：

**单一目的闸门**：一条消息里目的不唯一（既汇报进度又要加钱）？→ 只保留权重最高的一个 ask，其余降级为背景信息，或拆成下一条单独发。

过闸后按目的进入 A/B/D/E/F 场景模板。

### Step 3 · 金字塔倒转

把草稿的「思考顺序」（背景→过程→结论）强制倒转为「接收顺序」（结论→理由→细节）：
- 检查草稿结尾有没有藏着"简单说/也就是说/所以"——那句话就是真结论，挪到最前面。
- 删过程叙事（"我先试了 A 又换了 B 后来发现……"）——那是讲给自己听的。
- 独立信息点 ≤3 个为佳，超过 5 个必须分组打包（工作记忆上限 3-5 组块，Cowan 2001）。

### Step 4 · 中文微信礼貌层

- 结论前加**一句**缓冲锚点：称呼 + 事由前置（"X总，跟您同步一下进度"）。**缓冲的是语气，不是结论出现的时间点**——缓冲句之后第一句就是结论。
- 对内（老板、同事）不用「您」、不加缓冲句，第一句直接是事。对 GC、业主按 Step 1 的权力位置定礼貌层。
- 英文 WhatsApp/邮件用同一套结构：第一句是请求或结论加日期，不写 I hope this finds you well、kindly、please be informed 之类客套。
- 长内容合并成**一条**消息，内部用换行 + 序号（1/2/3）分层，禁止拆成多条刷屏（每条都震动对方手机一次）。
- 微信没有加粗：用【】标关键动作和时间（"【需要您确认】周五前回复选 A 还是 B"）。
- 禁语音（对甲方发语音是不对称权力信号）、禁裸"在吗"、禁"我能问个问题吗"这类空转开场。
- 不过度道歉："不好意思打扰"最多出现一次；真出错时道歉一句就转向"接下来怎么办"。

### Step 5 · 发送前自检闸门（全过才交稿）

1. **第一句测试**：对方只读第一句，知不知道你要说什么/要 TA 做什么？
2. **So What 测试**：每一块内容能答出"所以对 TA 意味着什么"吗？答不出就删。
3. **唯一 ask 测试**：整条消息是不是只要求对方做一件事？两件事拆两条消息或做成选项。
4. **限定词保留测试**：为了短，有没有删掉"但是/除非/前提是"？删了就补回来——丢限定词比啰嗦更贵。
5. **形态测试**：一条消息、有称呼、数字精确、时间点明确、结尾有【需要您做什么】。

## 场景模板（A/B/D/E/F）

### A · 进度汇报

重点 = 状态判断，不是工作量证明。

```
X总，同步下进度：整体正常 / 有风险 / 已延误（选一个 + 一句话为什么）。
本周完成：1)... 2)... 3)...（≤5 条，只讲结果不讲过程）
接下来：1)... 2)...
【需要您】XX 日前提供 XX / 无需您操作，下次同步在 XX 日。
```

- 客户没来问就该主动发——两次交付之间的沉默是乙方最常见沟通错误（Toptal）。
- "接下来"承诺要保守可兑现，不要理想化。

### B · 提方案 / 要决策

重点 = 让对方在选项之间选，不是开放式征求意见。

```
X总，关于 XX，我建议方案 A，理由是 XX。两个可选：
A：XX 天，¥XX，效果/取舍是 XX（推荐）
B：XX 天，¥XX，效果/取舍是 XX
【需要您】XX 日前定 A 或 B，定了我当天开工。
```

- 2-3 个等价选项优于单方案，经济结果和关系结果都更好（MESO 研究，ScienceDirect 六实验）；**超过 3 个反而有害**。
- 每个选项必须写清代价+结果，不是干巴巴列名字。
- 禁问"您觉得呢/您怎么看"——决策期用选项，开放式问题只留给探索期。

### D · 坏消息（延期 / 做不了）

重点 = 下一步方案先行，不是"不行"先行，更不是道歉先行。

```
X总，XX 的交付时间要调整：新完成时间【XX 月 XX 日】（比原计划晚 X 天）。
原因是 XX（一句真话，不甩锅）。
我已经 XX 来把影响降到最低。
对您这边的影响是 XX。
【需要您】如果 XX 和 YY 只能保一个，您优先要哪个？
```

- **发现即说**，不等临近截止日——所有来源的共识第一条。
- 缓冲用**真实原因**，不用无关表扬——三明治话术已被研究证伪（Ivey 2025：对方能识破表扬是缓冲垫，反而不知道你到底要说什么）。
- 结论先行 ≠ 拒绝先行：拒绝类内容，先行的"结论"是替代方案（"能做到 YY，XX 部分建议 ZZ"），不是"不行"三个字。
- 情绪敏感、预计要来回拉扯的，文字给完结论后补一句"细节我给您打个电话说"，把冲突升级风险转移到语音渠道。

### E · 超范围 / 加钱

重点 = 认可想法 + 客观引用约定 + 给两个选项，不辩论。

```
X总，XX 这个要求收到了。它在原来约定的范围之外（原约定见 XX/合同第 X 条）。
两个走法：
A：加进来，加 ¥XX，交付顺延 X 天
B：本期按原计划走，这个放二期
【需要您】选 A 或 B。
```

- 先确认收到（不否定对方，也不夸）→ 指出超范围（引用文档，不靠记忆争辩）→ 选项制收口，不问"您怎么看"。

### F · 催办 / 日常请求

重点 = 请求 + 截止时间在第一句，背景在后面。

```
X总，麻烦您【XX 日前】把 XX 发我——这周排期里 XX 环节等这个才能开工。
（背景可选，一两行）
```

- No-hello：问候和完整请求放同一条消息，禁止"在吗"→等回复→再说事的三轮往返。
- 一条消息一个 ask，结尾时间点明确。

## 流派共识与分歧（裁决规则）

五路调研的共识：**结论先行、一次说完、明确谁在什么时间做什么**——金字塔原理、BLUF（美陆军 AR 25-50）、Smart Brevity、Executive Summary 规范、No-hello 全部指向这三条。

三组分歧及本 skill 的裁决：

| 分歧 | 一派 | 另一派 | 裁决 |
|---|---|---|---|
| 直接 vs 缓冲 | 直接说，缓冲被识破反伤信任（Ivey 2025） | 对外部客户先给原因再给坏消息（商务写作教材） | 用**真实原因**当缓冲，不用无关表扬当缓冲；结论仍在最前 |
| 先问 vs 先说 | SPIN：报价值前先问痛点 | BLUF：汇报时结论先行 | 按阶段分：手上有结论→先说；需要对方的信息/认可→先问 |
| 给选项 vs 开放提问 | 决策期给 2-3 选项（MESO） | 探索期开放提问 | 探索期开放问，决策期选项问，绝不混用 |

**最重要的破除刻板印象**：中文≠必须委婉。学术证据（Yang & Zhen 2017）表明直接≠不礼貌，权力不对等场景中文使用者反而更直接。变量是权力关系——所以本 skill 对甲方场景加厚礼貌层，但**永远不把结论拖到消息后半段**。

## 反模式（改写时见一个杀一个）

1. 过程叙事当汇报（"我先研究了 A 方案，又试了 B……"）
2. 技术黑话不翻译——技术事实必须接"这对您意味着 XX"，或干脆不说（技术选型默认不进汇报，除非影响时间/价格）
3. "在吗" / "我能问个问题吗" / 语音轰炸
4. 道歉开场、道歉超过一句、"抱歉占用您时间"式自我贬值
5. 多条短消息刷屏
6. 一条消息塞多个 ask
7. "您觉得怎么样？"式开放收尾（决策期）
8. 模糊数字（"大概两三万""下周左右"）
9. 为了短删掉限定词和风险条件——**该删的是废话和寒暄，不是复杂性**（Smart Brevity 被批评最狠的就是这点）
10. 把决策甩回给客户（"您是老板您定"）——用选项制收窄，不用模糊回应模糊
11. 把"润色一句话"的轻量请求套满整套模板——原文已经结论先行、只有一个 ask 时，只做措辞/礼貌层微调，不强行拆结构、不强行加【】和序号

## 输出格式规定

1. **成品必须可直接复制发送**：完整称呼、真实内容填好，不留 [占位符]（除非用户真的没给该信息，那要在改动说明里点名要）。
2. 默认给 **1 个成品**；场景 D/E（坏消息/要钱）或用户拿不准语气时，给**直接版 + 软化版**两个。
3. 成品后附 **≤3 行改动说明**（改了什么结构、为什么），不写论文。
4. 用户草稿里的事实一个不许编、一个不许丢——本 skill 只动结构和措辞，不动事实。

## 诚实边界

- "占用您一分钟""先说结论"这类前置短语只有**惯例证据，没有效果实证**——当作通行做法用，别当作被验证有效。
- 探索期/共创式讨论、需要悬念的说服叙事、纯关系维系的寒暄，**不适用**结论先行——本 skill 不会自动识别所有这类场景，用户对现场关系的判断优先于模板。
- 权力位置判断依赖用户提供的上下文，skill 默认"对方是甲方"，判断错了礼貌层会过厚或过薄。
- 结构对了不等于事成——报价被接受、延期被谅解，最终取决于交付质量和关系存量，skill 只保证"话说到点上"，不保证结果。
- 调研时间：2026-07-09，方法论快照见 `references/research/`（5 份调研笔记，含全部来源 URL 与可信度分级）。
